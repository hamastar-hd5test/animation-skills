# style-pack：一個場景，N 種畫風

觀眾看得懂比較，是因為**只有畫風在變**。所以這份 skill 的全部工夫都在兩件事：把場景鎖死、把每種畫風說到「看得見」。

## 原則

1. **構圖是常數，畫風是變數。** 先把場景拆成錨點清單（主角、配角、背景元素、視角、比例），每一張都逐項核對。少一盞路燈，比較就不成立。
2. **先定格，再動畫。** 靜態圖確認不走樣才進動畫；直接生影片，畫風會在動作裡漂掉。
3. **動作跟著材料走。** 粉筆是被畫出來的、像素一格一格跳、積木卡進去、CGI 是光在掃。動法寫在畫風條目裡，照用。
4. **失敗就減字，不加字。** 某個畫風一直做不對，把畫風描述砍到一句最關鍵的「看得見」，不要再疊形容詞。
5. **一個主角、少量物件。** 場景越簡單，十種畫風越乾淨；主角超過一個就先問要不要簡化。
6. **先說出處。** 照 web-style-recipes 核心原則 6：畫風有 A 編號的講那件經典，寫「待查」的先查一件代表作再做。

## 畫風從哪裡來（唯一來源是 web-style-recipes，不在本 skill 複製）

| 庫 | 檔案 | 怎麼拿來用 |
|---|---|---|
| 場景畫風 S01–S33 | `~/.claude/skills/web-style-recipes/references/scene-styles.md` | 現成：「prompt」當畫風句、「動法」當動畫方向、「最該檢查」當驗收 |
| 美學 A01–A20 | `~/.claude/skills/web-style-recipes/references/aesthetics.md` | 要轉譯：「看得見」＋「規則」→ 畫風句；動法照 `references/translate.md` 的表 |
| 互動配方 01–11 | `~/.claude/skills/web-style-recipes/references/styles/NN-*.md` | 只取「視覺特徵清單」當畫風句，互動流程丟掉（風格包不能玩）；動法照 `references/translate.md` |

使用者只說名字時，先在三個庫比對（「像素」同時有 S04 與 A17：S04 是場景畫風、A17 給規則與出處，合起來用）；Claymation、剪紙、Bauhaus 這類英文叫法先查 `scene-styles.md` 的「別名對照」。比對不到就列最接近的 2～3 個讓他選。只讀選到的那幾條，不要整份讀完。

要做成**有旁白、配樂的整支影片**、要把某個畫風**改成自己的品牌版本**，或畫風要寫到能撐整支片的細度（11 欄影片級畫風卡），或畫面裡有角色要走路、有東西要晃時，讀 `references/film.md`。

## 流程

1. **定場景**：有圖就看圖，沒圖就請使用者描述。寫出錨點清單（格式見 `references/translate.md`「錨點清單」），給使用者確認一次。主角太多或畫面太雜就提議簡化。
2. **選畫風**：沒指定就挑 10 種彼此差最多的（線條、印刷、手作、遊戲、3D 各取兩種，例如 S05、S01、S15、S24、S16、S20、S04、S25、S09、S26）；使用者點名就照點名。同一包最好同一個來源層級，混 A 與 S 時告訴使用者哪幾張會比較「重」。
3. **組 prompt**：每種畫風一份，用下方主模板，`{畫風句}` 填該條的 prompt 或轉譯結果。另寫一句動畫 prompt（主模板第二段）。
4. **出定格**：使用者有生成工具就交 prompt 給他；這個環境能用的路線見下方「出圖路線」。每張回來照錨點清單逐項打勾，缺項的只修那一張。
5. **做動畫**：定格全部通過才動。動作小而能循環：主角輕移、背景微漂、燈光閃、輕微視差。每種畫風照它的動法，不要十張用同一種緩動。
6. **匯出風格包**：同比例、同長度、同檔名規則（`NN-畫風英文短名`）。附一張對照表（並排縮圖＋名稱＋適合用途），HTML 或 PDF。要剪成一支短影音時，照下方「展示片的兩種排法」。

## 主模板

```
Recreate the scene below in {畫風名}. Keep the composition exactly: {錨點清單，一行一項}.
Same framing, same aspect ratio {比例}, same proportions and positions. Change only the visual treatment: {畫風句}.
Keep silhouettes readable and shapes clean so the frame can be animated later with a subtle loop.

Animate this still: {動法}. Subtle, loop-ready, {秒數} seconds, no new objects, camera and composition unchanged unless the motion says otherwise.
```

第一段給圖像工具，第二段給影片工具（附第一段做出來的定格當起始畫面）。

## 出圖路線

先看使用者手上有什麼，再挑路線（2026-11-22 整理自 Higgsfield 的 Genjutsu／3D Jutsu 教學）：

| 手上有 | 做法 | 鎖住的是 |
|---|---|---|
| 一支影片 | 影片換外觀：整支片換畫風，動作與鏡頭不變 | 原片的動作與運鏡，錨點清單照原片寫 |
| 只有一個想法 | 先把場景建成一個 3D 小世界（或一份 SVG 場景）、放好攝影機拍一次，再逐一換皮 | 同一個世界、同一條動作、同一個鏡頭，所以 N 種畫風最好比 |
| 一張圖 | 每種畫風先出一張定格，再各自做成動畫 | 那張圖的構圖；每段動畫要從自己的定格起跑 |

| 路線 | 什麼時候用 | 做法 |
|---|---|---|
| 交 prompt | 使用者自己有 Midjourney、Runway、Kling 等 | 交付 prompt 表＋錨點清單＋驗收表，請他回傳定格再核對 |
| 生成工具 | 這個 session 有圖像生成工具（例如 Canva 的生圖） | 先用一種畫風試一張，確認比例與錨點都對再批次 |
| Higgsfield MCP | Dex 要用付費的影片生成，且已自己接好連接器（claude.ai 的 Customize → Connectors 加自訂連接器，官方網址 `https://mcp.higgsfield.ai/mcp`） | `/genjutsu <畫風>` 把影片換外觀（4～30 秒、照影片收點數，開始前會報價，要 Dex 同意）；`/3d-jutsu <想法>. <畫風> style.` 建 3D 小世界拍攝（建與拍不收點數）。要接或要花點數都先問 Dex。完整指令、三組畫風名單、其他指令（打光調色、字幕、解說片、產品轉圈）在 `references/higgsfield.md` |
| 寫程式畫 | 要精準一致、要可改、或沒有生成工具 | 場景先畫成一份 SVG／three.js 場景，每種畫風是一組換皮（線條、濾鏡、材質、打光），動畫寫在程式裡；各條的「網頁做法」就是起點。要出影片交 `remotion-best-practices` 或 `sui-motion-graphic-reel` |

寫程式路線的做法：場景幾何只寫一份，每種畫風是一個函式吃同一份幾何、輸出自己的 SVG；範例在 `~/.claude/skills/web-style-recipes/tests/style-pack/index.html`（S05、S01、A09 三種，2026-11-22 實測）。

**檢查動畫要凍結時間再截圖**：無頭 Chrome 的 `--virtual-time-budget` 不會推進 CSS 動畫（`currentTime` 一直是 0），截到的畫面時間點不可信。在頁面載入後執行 `document.getAnimations().forEach(a => { a.pause(); a.currentTime = T })`，T 用網址 hash 帶入，對 1.5／3.5／6／8.6 秒各截一張拼成時間軸再看。無頭 Chrome 的視窗寬度有下限，手機寬度要用 DevTools 模擬。

寫程式路線的好處是構圖天生不會走樣，但 S03、S06、S09、S10 這類 3D 畫風要用 three.js，成本高，先跟使用者確認。

## 驗收（每張都過）

- 錨點清單逐項都在，位置與大小關係沒變
- 畫風一眼認得出，且與同包其他張不重複
- 該畫風的「最該檢查」那一格過了（見 scene-styles.md 對照表；A 與配方畫風看 `references/translate.md`）
- 動畫：首尾可接成循環、沒有新物件、動法符合該畫風
- 對外用的：沒有品牌商標（S03 積木特別注意）、沒有真人臉

## 展示片的兩種排法（把風格包剪成一支 9:16 短影音）

2026-11-22 從三支「十種 Claude 動畫畫風」Reel 整理（@vec3.motion、@anylancer、@matt_penny_applied_ai）。兩種都是一種畫風約 1.5～3 秒、開頭三秒就讓人知道「接下來有 N 種」。

| | 清單揭曉 | 接力穿越 |
|---|---|---|
| 結構 | 左邊一欄 1～N 的編號清單，輪到的那條亮起變粗；右邊一個直式手機框放當前畫風；框下寫畫風名＋一句場景 | 一個連續動作（一顆球、一個角色）從第一個世界一路走到最後一個，每進一個世界就換畫風 |
| 每段長度 | 約 1.4～1.7 秒，節奏快、同一個鏡頭；每種畫風都從同一個主動作的開頭重播（例如火山每次都從冒煙到噴發），觀眾比的是同一刻 | 約 3 秒，畫風名做成那個畫風的字（ASCII 用終端字、剪紙用剪紙字），旁邊進度 n/N |
| 轉場 | 硬切，清單往下一條 | 動作本身穿過去：球滾出這一格、從下一個世界滾進來，或擦換 |
| 結尾 | 所有畫風縮成小卡，排成兩三列橫向跑馬燈 | 回到清單，每條打勾，旁邊一張總覽格 |
| 適合 | 構圖完全一樣、要比畫風 | 想要故事感、一支片看完一整段因果 |

兩種都照錨點清單鎖構圖；接力穿越鎖的是「那個連續動作的位置與速度」，每段交接時球的位置要接得上。字幕、清單字與畫風名照 `references/film.md` 的字幕停留規則；結尾的行動呼籲要 Dex 定，不沿用原片的「留言拿連結」。

## 範例

使用者：「把官網首頁那張『筆電＋咖啡杯＋窗外城市』做成 5 種畫風的短動畫。」
→ 錨點：筆電（左下，螢幕亮）、咖啡杯（右下，冒煙）、窗框（上半）、窗外城市剪影、16:9 → 選 S01 發光線稿、S05 黑板粉筆、S07 扁平向量、A09 Riso、配方 02 熱感應的視覺 → 五份主模板 prompt → 定格逐項核對（Riso 那張咖啡煙不見，只重做那張）→ 動畫：S01 螢幕光呼吸、S05 線一筆一筆畫出、S07 三層視差、A09 套色微偏抖動、熱感應咖啡杯冒熱的熱斑 → 匯出 5 支 6 秒 16:9＋一張對照表。
