# 技術規格與已知的坑

標「未實測」的是教學說法，本機跑過後改成實測值並記日期。

## 環境（未實測）

Python 3.11+、FFmpeg。套件：faster-whisper、opencc-python-reimplemented、pyJianYingDraft、opencv-python、mediapipe、numpy、pillow、requests、jieba。

## 逐字稿

- faster-whisper large-v3（int8 可），OpenCC 轉繁體
- 在靜音處切段，每段 ≤18 秒；整檔丟進去會鬼打牆重複卻不報錯
- 中文快語速時詞級時間不可靠，不當下刀依據
- 專有名詞用兩種提示詞各轉一次交叉比對

## 跳剪

- 能量偵測：核心門檻約 P90−14dB，保護線約 P90−10dB 接住小聲尾字
- 保留空隙：句末 0.08–0.12 秒、逗號約 0.05 秒、句內 0.03 秒
- 只在標點下刀，接點 16ms 交叉淡化，不伸展人聲

## 字幕

- 一拍一行，不疊兩行；一行 ≤10 字、每組 2–8 字
- 強調色約 20–30%，留給數字、原話、金句、步驟動詞、CTA
- 雙語預設關閉，Dex 要才開

## B-roll

- 同一支最多 2 次且相隔 25 秒以上；單鏡 ≤7 秒
- 切換落在字幕組界；教學片每分鐘 ≤20 刀

## 分身（未實測，串接前查 HeyGen 官方文件）

- API 當時為 v3：`POST /v3/videos`，type 為 avatar，engine 指定 avatar_v 並帶訓練分身的 reference_look_id，1080p、9:16；不指定 engine 會落到舊引擎
- 音檔用 mp3，不用 m4a。段前留 0.3 秒、段間留 0.6 秒靜音，接成一條；回來切開時幀數用 `round(t1×fps)−round(t0×fps)`
- 臉不足 7% 時，剪輯推近約 1.06 倍
- 用照片做的分身手不會動，要用影片訓練
- API 參數放錯層會被默默忽略，每次都要檢查手有沒有動

## 聲音（未實測）

MiniMax 克隆樣本 10 秒–5 分鐘；配音輸出 44.1k wav。

## 音效與配樂

自選約 5 顆固定音效，分輕重，只放重點字。教學片每分鐘 ≤8 顆、重音效間隔 ≥9 秒。配樂獨立一軌。配樂與音效要確認可商用。

## 合成與交付

- 逐幀合成，不依賴 ffmpeg overlay；最後轉檔加 `-r 30 -fps_mode passthrough`
- 分段接合時先去掉各段音軌再 concat，再混音，不加 `-shortest`（2026-11 在另一個專案 video-shotcraft 練功房片實測：帶音軌 concat 會產生時間戳洞，`select=between(n)` 量不出來，要看實際 PTS）
- 長渲染用前景分段跑，設上限、壓低並行數（同一專案實測：背景渲染被系統砍掉後，等通知會空等）

## 剪映草稿（未實測）

- 2026-11-04 查過：本機沒有安裝剪映，也沒有草稿資料夾。要出草稿時先請 Dex 安裝，草稿路徑從剪映設定裡看，不要猜
- 核心是 `draft_content.json`，要另外登錄到草稿資料夾的 `root_meta_info.json`，剪映開著時不要寫
- 只有分身片段、中間留空的草稿放非主軌，否則主軌磁吸把片段擠到開頭
- 看不到草稿時：完全關閉剪映再開，檢查索引與資料夾路徑
- CapCut 國際版格式未驗證
