# sprite-stack：切片堆疊的像素立體

畫面裡沒有 3D。每個物件是一疊平面像素圖，一層高度一張，像把吐司橫切；由下往上畫，每層抬高 1px，所有切片轉同一個角度，眼睛就會把它看成一個從斜上方俯視的實體。

## Dex 的定案（2026-11-23）

看過 TibaMe 11/24 兩支切片堆疊短片後，Dex 說：「我喜歡這種風格，未來就用這種風格做短影音，但要持續優化。」所以：**DayDreamDex 的短影音預設用這個畫風**，除非當次另有指定。每做完一支，把 Dex 的修改意見與新撞到的坑寫回 `references/`，下一支從上一支的專案複製，不從零開始。目前最新的基底是 `~/video-shotcraft-trial/tibame-1124-shorts/`（`src/stack/`）。

**預設要開的三項**（Dex 2026-11-23 看過比較片後拍板，做法見 `references/optimization-directions.md` 方向一）：
1. 開場主角放大到佔畫面寬六成以上、往下放，素底當天空，後面加靜止遠山與圓潤的雲（雲要用最高的那張字卡檢查不會被擋）。
2. 主角獨處超過 3 秒時排一個看得清楚的小事件（例：窗戶亮兩下）；太小的事件（20px 的小鳥）沒有用。
3. 全景空檔讓鳥群從畫面下半掠過，避開字卡切點與招牌落下的拍子。
雲影、停格節奏留成開關，預設關。程式在 `tibame-1124-shorts` 的 `src/town/codedex.ts`，旗標 `TownLook`，組合 `LOOK_V2`。

Dex 對第一版的意見（做下一支時先對照）：內容提到的每個重點都要各自講到，不能只用一排站名帶過；有對應的原圖或工作表要帶進片裡，再轉場到片尾。

## 起手式：先複製能跑的

`assets/starter/` 是驗證過的最小版本，新案子從這裡複製，不要從零寫：

| 檔案 | 內容 |
|---|---|
| `stack.js` | 核心純函式：`Volume`（體素格與形狀）、`toSlices`／`lightSheets`（切片＋三階明暗）、`fromStrip`（讀切片長條圖）、`renderStack`（疊起來）、`outline`（單一輪廓）、`blit`、`sortByGround`。瀏覽器與 Node 共用，無相依套件 |
| `stack.test.js` | 12 個測試，`node --test stack.test.js` |
| `index.html` | 示範：一座塔兩棵樹，自動慢轉、可拖曳；`?turn=20` 固定角度、`?slices=1` 把切片拉開看原理 |

`renderStack` 是逐像素反查最近鄰，不走 canvas 的旋轉變形。原因：canvas 就算關了平滑，旋轉後的圖形邊緣仍會被反鋸齒，像素會糊。

## 五條不能破的原則

1. **整疊一起處理，不逐片處理。** 輪廓是整疊畫完後把剪影外擴 1px；多個物件按落地點的 y 整個排序。逐片描邊會在身體上留雜點線，逐片排序會穿插錯亂。
2. **一切落在整數像素。** 先畫進低解析畫面（直式 270×480、方形示範 160×200），再整數倍放大、關平滑；位置全部取整。糊＝某處開了平滑，閃＝某處用了小數位置。
3. **美術用程式長出來。** 物件寫成體素模型（一邊 16–48 格），用方塊、圓柱、圓錐、球、楔形組合與挖空，再自動切片。不手繪切片、不放圖檔。
4. **平塗、少色、三階明暗。** 每個物件 4–6 色，每色亮／中／暗三階，光源固定在螢幕上（每 45° 預建一組切片）。漸層、反鋸齒、切片裡的 1px 細條紋，疊起來都會變成一團雜訊。
5. **先把一個物件做到好看。** 主角物件單獨在素底上好看了，才加地面、其他物件、動態、鏡頭。一個不好看，一百個也不會好看。

鏡頭俯角用垂直壓扁表示，預設 0.75，不低於 0.6（再低屋頂會薄得像紙）。

## 物件從哪裡來：兩條路

- **用程式寫體素模型**（下一節）：建築、塔、樹這類由基本形體組得出來的。每 45° 重新打光，轉起來明暗正確。這是我們短影音的主力。
- **從四張視圖雕出來**（`vendor/sprite-stacking/`，danielwh2/sprite-stacking，MIT）：手上有圖、或外型細節多（車、角色、有招牌的店面），或要給遊戲引擎的 16 方向 sprite sheet、要互動展示頁時。雕出的切片圖用 `fromStrip` 讀進我們的核心。做法、限制與實測結論在 `references/four-view-carving.md`。

## 做一個新物件

```js
const v = new Volume(34, 34, 44);            // 寬、深、高
v.cylinder(17, 17, 2, 28, 10, 7, 1);          // 中心、z 範圍、底半徑→頂半徑、色號
v.box(15, 25, 2, 19, 28, 9, 6);               // 門
v.cylinder(17, 17, 30, 41, 9, 0.5, 2);        // 頂半徑接近 0 就是圓錐
const sheets = lightSheets(v, PAL);           // PAL: { 色號: [亮, 中, 暗] }
const img = outline(renderStack(pickSheet(sheets, turn), turn, 0.75, 1));
blit(buffer, img, x, y);                      // x, y 是落地點
```

流程固定是「寫模型→截圖看→改」：用 `?turn=` 截 3–4 個角度加一張 `?slices=1`，看圖挑錯再改，不要只憑程式碼判斷好不好看。看圖挑錯的對照表在 `references/technique.md`。

會動的零件（葉片、旗子、光束）各自成一疊；軸是水平的旋轉（風車葉片）沒辦法靠轉切片做，要預建 12–16 個角度的模型輪播。

## 交件前

- `node --test stack.test.js` 全過（改了核心才需要）。
- 截圖看過：至少 3 個角度，輪廓單一、沒有雜點線、前後遮擋正確。
- 會動的：慢速旋轉或鏡頭移動時抽連續幾格比對，沒有閃爍。
- 要錄片的：同一個種子跑兩次，同一格畫面相同。
