# 從四張視圖雕出物件（整合 danielwh2/sprite-stacking）

工具在 `vendor/sprite-stacking/`（MIT，來源與安全檢查見該資料夾的 `SOURCE.md`）。原文全文是 `vendor/sprite-stacking/UPSTREAM.md`，引擎接法是 `engines.md`；這份是我們的用法與實測結論。

## 什麼時候用它，什麼時候用我們的體素程式

| 手上有 | 走哪條 |
|---|---|
| 一個想法，物件由方塊、圓柱、圓錐、楔形組得出來（建築、塔、樹、車） | 我們的 `Volume` 寫模型（SKILL.md「做一個新物件」）。光照每 45° 重算，轉起來明暗正確 |
| 一張圖、或要很多細節的外型（車身、角色、有窗框招牌的店面） | 先做四視圖，用 `views_to_slices.py` 雕刻，再用 `fromStrip` 讀進我們的核心 |
| 生圖工具做出來的四視圖 | 同上，先過「雕刻前檢查」 |
| 要給遊戲引擎、要 16 方向 sprite sheet、要互動展示頁 | 用它的 `viewer.html`（轉台、場景、光影、天氣、16 方向匯出） |

**明暗會跟著轉**（2026-11-25 實跑發現）：四視圖裡畫好的亮暗面會被雕進體素，物件轉 180° 時原本的亮面轉到背光側仍然是亮的。所以：
- 給雕刻用的視圖，明暗要畫得淡（或 `--shade 0.12–0.15`、甚至全平塗），立體感交給整疊的輪廓與頂面。
- 要正確光影就加 `--normals normals.png`，渲染時依法線重新打光（它的 viewer 就這樣做）。我們的 `renderStack` 目前只吃顏色，用法線打光是待做的優化。

## 流程

1. **四視圖**：一列，順序 TOP、SIDE、FRONT、BACK，純白底、各圖之間至少 40px。TOP 正上方看下去、前方朝下；SIDE 前方朝左。四張同比例：TOP 長＝SIDE 長、TOP 寬＝FRONT 寬、SIDE 高＝FRONT 高。每張 1px 深色外框、平塗、無反鋸齒。
2. **來源三選一**：有生圖工具就用 UPSTREAM.md 裡那段 prompt（只換主體，其他照抄，生圖要先問 Dex 花費）；Dex 給圖就用；都沒有就自己用 PIL 以原生解析度一格一格畫，放大 8 倍貼成一列（範例：scratchpad 實跑的圓塔腳本，做法就是 UPSTREAM.md 的路線 c）。
3. **雕刻前檢查**：方向、比例、硬邊、會被填實的空洞（四張剪影都看不到的凹處會被填滿，例如卡車貨斗）。
4. **雕刻**：
   ```bash
   python3 -I ~/.claude/skills/sprite-stack/vendor/sprite-stacking/views_to_slices.py views.png slices.png \
     --slices 34 --preview check.png --html viewer.html
   ```
   自己畫的視圖，`--slices` 設成 SIDE 的原生高度（含外框）。圓的東西（塔、氣球、盆）加 `--round`；不是車輛一律加 `--top-nose down`。其餘參數表在 UPSTREAM.md 第 2 節。
5. **先看 `check.png`**（四張抽出的視圖、四個角度、拉開的切片）再寫任何整合程式。
6. **接進我們的管線**：讀 `slices.png` 的 RGBA 像素，`fromStrip(data, 寬, 高, 層數)` 得到 sheet，之後跟 `toSlices` 的結果一樣用（`renderStack`、`outline`、`blit`）。寬度除不盡層數會直接報錯。

## 雕刻的規則（它的 Lessons 表，我們會撞到的）

- 細的東西（柱、繩、天線）至少畫 2px 寬，1px 的轉起來會時有時無；腳本會警告。
- 比底座窄的圓形部分（塔身、氣球）不加 `--round` 會雕成方的。
- 從牆面凸出的小東西（花台、招牌）會沿整面牆雕出一條平台：小凸出物直接畫平在牆上；煙囪要給它一段平的屋脊站。
- 視圖內被包住的背景（繩子、腿之間）會被雕成實心：每個空隙都要通到視圖外面。
- 物件要置中，底座偏一邊，轉的時候會繞圈。

## 它有、我們原本沒寫的渲染規則（已併入 technique.md／optimization-directions.md）

- 旋轉中心要對稱。我們的 `renderStack` 已驗證沒有半格晃動（測試「偶數寬的切片轉任何角度，形狀中心都不偏移」）。
- 載入切片圖時驗證寬度能被層數整除（`fromStrip` 已做）。
- 球體要補償壓扁，否則會變成直立的蛋：垂直半高 `R_z = R_xy · √(1 − squash²) / spacing`。
- 會擺動的固定物（旗、草、海帶）：每一層水平位移 `sin(t·頻率 − z·波長 + 相位) · 幅度 · (z/(層數−1))²`，底層不動、頂端擺最多。
- 「蓋起來」的進場：逐層抬升時，揭露前緣要推到 `層數 + 過渡寬度` 才結束，否則最上面幾層會在最後一格突然跳到位。不要用透明度淡入或失焦轉場。
- 會動的生物：做幾張同尺寸、同中心、同層數的姿勢切片圖輪播，並多留幾層上下空間，翅膀、尾巴才不會被切掉。
- 高的物件投影子：沿太陽方向逐層投影，邊緣用 Bayer 4×4 抖色，不要用通用的橢圓影子。
- 交件前在成品實際大小看一次（例如手機 390px 寬），不加標示也認得出是什麼、朝哪邊。
