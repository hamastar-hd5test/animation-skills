# 持續優化的方向

Dex 2026-11-23 定案短影音用切片堆疊風，並要求持續優化。這裡列「下一支可以試的方向」；試過有效的，把結論搬進 `technique.md` 或 `scene-and-timeline.md`，並在這裡標已採用。

## 方向一：Codédex 式的分層與逐格節奏（Dex 2026-11-23 指定列入）

來源：另一個 session 對 https://www.codedex.io/ 首頁的拆解，全文在 `~/.claude/skills/pixel-fx/references/codedex-study.md`（唯一來源，數字以它為準，這裡不複製）。只學做法；對方的圖、角色、字型都不取用。

它跟切片堆疊是兩種做法：Codédex 是低解析的平面分層圖加預先畫好的逐格動圖；我們是用程式疊出體積。可以借的是**節奏與分層的觀念**，不是換掉堆疊。

| Codédex 的做法 | 搬到我們的短影音 | 狀態 |
|---|---|---|
| 遠景靜態、近景才動，由遠到近分 3–5 層 | 堆疊場景後面加 1–2 層平面遠景（天空、遠山），前景加一層草或雲；鏡頭移動時各層速度不同，直式畫面上下的空白就有東西 | 未試 |
| 天空極慢平移（200 秒才一輪） | 遠景層每格只動零點幾個低解析像素，累積取整；畫面永遠不是死的 | 未試 |
| 動的格數少、每格停得久（每格 100–180 ms） | 會動的堆疊零件（旗、火、煙、走路）用「停格」而不是每格都變：30fps 下每 3–5 格才換一次姿勢，像素感比滑順補間強 | 未試（目前的走路與旗是每格算） |
| 待機動畫拉到 8–10 秒才重複，小事件散在裡面 | 主角物件停在畫面上超過 3 秒的段落，排一兩個偶發小事件（窗戶亮一下、鳥飛過、煙換方向），解決「最靜的一段」 | 未試（片 B 工坊段是已知的靜止段） |
| 標題「動一下、停很久」（掃光不到 1 秒，停 3.5 秒） | 字卡與招牌出現時掃一道光就停，不要一直閃 | 未試 |
| 像素字只給標題與標籤，內文用一般字 | 招牌、站名用像素字；多行字卡維持現在的圓體 | 已是現況 |
| 低解析原圖整數倍放大（480×320 放 3 倍） | 與我們的 270×480 ×4 同一個原則 | 已採用 |
| 整個主視覺約 150 KB | 提醒：少色、少格就夠好看，不必加細節 | 觀念 |

### 第一次試驗結果（2026-11-23，片 A 兩段 5 秒並排比較；Dex 選了前三項當預設，已寫進 SKILL.md）

比較片在 `~/Documents/個人品牌/TibaMe-1124分享會/社群轉發-20261121/短影音/風格試驗-codedex/`；程式開關是 `TownFilm` 的 `codedex` prop（`src/town/codedex.ts`），預設關。

| 項目 | 結果 |
|---|---|
| 開場主角放大到佔寬六成、往下放＋靜止遠山與雲 | 明顯加分，建議預設。遠山上的扁雲是階梯狀、偏生硬，要重畫 |
| 獨處段落的窗戶亮兩下 | 加分 |
| 前景鳥群掠過（放下半部） | 加分，成本幾乎為零 |
| 近層丘陵極慢平移 | 小加分，滑過去不一定注意到 |
| 地面雲影 | 沒加分：手機上很淡，調深就髒，每格多 2.4 ms |
| 停格節奏（煙、火星每 4 格一換） | 沒加分：零件太小，正常播放看不出差異；留成開關 |
| 屋頂停一隻小鳥 | 沒加分：5 倍下約 20 px，看不到。小事件要「看得清楚」才有用 |

實作上的坑：
- 平面遠景畫在「地面之後、物件之前」，而且只畫在素底那個顏色上，地面往外長時會自然蓋過，不用另算遮罩。
- 直式畫面上半是字卡與招牌，前景層放在那裡會被 React 圖層整個蓋住，前景要排下半部。
- 停格要對「事件開始後的經過時間」取整（`held(f − at)`），對 f 本身取整會讓爆點晚 0–3 格、離開拍點。
- 鏡頭有旋轉時，要把東西放在某物件上，用「物件投影點＋畫面座標偏移」，不要用世界座標硬對。
- `remotion render --frames=a-b` 出片段時配樂會自動對到那段，可直接做比較片。

做第一支要試這個方向的片時：先只加「遠景兩層＋停格節奏」兩項，跟不加的版本各出一段 5 秒比較，給 Dex 選，再決定要不要變成預設。（已於 2026-11-23 做過，見上表。）

## 方向二：從第一批成片看到的問題

來源：2026-11-23 TibaMe 11/24 兩支片的自評與 Dex 的意見。

- 開場主角物件在素底上偏小、畫面下方空：主角放大到佔畫面寬六成以上，或讓地面早一點出現。
- 暗場（未知區）容易被看成空畫面：暗處要有看得出形狀的剪影。
- 停在同一個取景超過 4 秒就顯得靜：排小事件，或讓鏡頭極慢地飄。
- 引路角色（貓頭鷹、鹿）目前只在片尾卡：試做體素版角色，或讓平面角色固定在字卡旁。
- 內容的每個重點要各自講到；有原圖或工作表就帶進片裡再轉片尾（Dex 意見，已寫進 SKILL.md）。

## 方向三：上游 sprite-stacking 的做法（2026-11-25 整合）

| 做法 | 我們可以怎麼用 | 狀態 |
|---|---|---|
| 物件位置與鏡頭用小數螢幕像素，只在最後貼到 1080 畫面時取整一次 | 我們目前在 270×480 低解析畫面取整再放大 4 倍，移動時一步是 4 個螢幕像素。慢速橫搖時改成「場景在低解析畫，鏡頭位移在放大後的畫面上做小數偏移」，可能更順 | 未試 |
| 法線圖（`--normals`）＋渲染時打光 | 雕出來的物件也能正確受光；也可以做時間變化（白天→黃昏→夜晚、窗戶自動發光） | 未試 |
| 發光遮罩（`--emissive`） | 夜景時窗戶、招牌、車燈自動發光，配合片尾或「亮燈」的段落 | 未試 |
| 天氣（雨的水面倒影、雪堆在朝上的面） | 季節或情緒段落 | 未試 |
| 16 方向匯出 | 練功房或小遊戲要用可轉的角色、道具時 | 未試 |
| 多姿勢的生物切片圖 | 讓引路角色（貓頭鷹、鹿）也變成堆疊體，而不是平面圖 | 未試，對應方向二的「引路角色沒進場景」 |

## 方向四：像素運鏡（Instagram @science_in_8bit 的 Reel，2026-11-25 讀取）

那支片的主張：同一張像素畫，沒有鏡頭只是一張圖，有了鏡頭才是一部片。畫面全部用程式畫，沒有用 AI 生影片。三個鏡頭依序是拉遠、滑動變焦、升降再落定，最後停在燈塔上「等光」，等光束掃過才切。

| 做法 | 我們可以怎麼用 | 狀態 |
|---|---|---|
| 拉遠：從主角近景退到全景，交代主角在哪 | 片頭第一鏡從主角物件退到整個場景，比一開始就給全景有記憶點；照 `scene-and-timeline.md`「推近拉遠」的做法，停住時回到整數倍 | 未試 |
| 滑動變焦：主角大小不變，背景跟著變大或變小 | 要先有方向一的分層遠景才做得到：主角層縮放固定，遠景層反向縮放。中途允許非整數倍，頭尾兩端要是整數倍 | 未試 |
| 升降再落定：沿著高的物件由下往上搖到頂，easeOut 停住 | 高物件（塔、書堆、伺服器機櫃）的介紹鏡；停住那一格對拍點 | 未試 |
| 等光：構圖停住後，等場景裡一個光源事件（光束掃過、窗戶亮起）再切 | 解決方向二「同一個取景停超過 4 秒就顯得靜」；切點放在光剛掃過之後 | 未試 |
| 天空用 5–7 條橫向平塗色帶，由上到下色相漸移，不用漸層 | 和 `technique.md` 的平塗限色一致，遠景天空直接用這個 | 未試 |
| 觀景窗外框：四角括號、REC 紅點、時間碼、段落號「01 / 03」配大字鏡頭名與一行斜體小字 | 只用在講方法、講鏡頭的片；一般片不加，會跟字幕搶視線 | 未試 |
| 開場對照：上下兩格，上格「沒有鏡頭」不動，下格「有鏡頭」在動；接著上格往後傾倒退場 | 適合「同一件事換個做法就不一樣」的主題，例如手動流程對自動化流程 | 未試 |
| 收尾三張分鏡卡（01 拉遠／02 滑動變焦／03 升降＋落定），每張是該鏡頭的縮圖 | 片尾回顧；縮圖用真正出片的畫面，不另外畫 | 未試 |

觀察：拉近時像素格跟著變大（升降那段的磚塊比全景時大），代表他們把整張像素畫放大，不是重畫成更細的像素。這和我們「場景固定畫 270×480，推近時裁中間再放大」的做法一致，不用改引擎。
